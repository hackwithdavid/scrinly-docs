Credits are charged by completed product component.

| Component | Credits |
| --- | ---: |
| Screenshot | 1 |
| Regions | +2 |
| Platform Visual Style Guide generation or regeneration | +3 |
| Platform Visual Style Guide cache hit | +1 |
| BYOK Visual Style Guide generation or cache hit | +1 |
| Visual diff | 1 |

A platform-funded screenshot with regions and a generated Visual Style Guide is 6 credits. The same request with an AI cache hit is 4 credits; BYOK is 4 credits.

Screenshot-cache hits preserve the screenshot and region tariff. Caching reduces Browser Rendering work and latency, not the published credit cost. A public screenshot batch reserves one screenshot credit per accepted item.

## Refunds

- A failed screenshot or primary upload refunds the complete request.
- A region-only failure returns the stored screenshot and refunds the two-region increment.
- A Visual Style Guide failure returns the screenshot and regions with `status:"partial"`, refunds only its AI increment, and includes `styleGuideError`.
- A failed diff refunds its one credit.
- Status polling and monitor listing are free.

When Scrinly cannot know the Style Guide cache status before generation, it charges the maximum and synchronously refunds the difference after settlement. Successful responses expose `credits.charged`, `credits.refunded`, and `credits.net` when the operation has additive settlement.

---
title: "Authentication"
description: "Authenticate server-to-server requests without leaking credentials."
---

Send your Scrinly API key in the bearer header on every request:

```http
Authorization: Bearer $SCRINLY_API_KEY
```

Keys are account-scoped. Status jobs, monitors, runs, baselines, and recipients owned by another account return `404`, while a missing, invalid, or revoked key returns `401`.

<Warning>
  Keep Scrinly keys out of browser code, query strings, analytics, logs, screenshots, and webhook payloads. Public documentation intentionally does not offer query-string authentication.
</Warning>

## OpenAI bring-your-own-key

Visual Style Guide requests may use an ephemeral OpenAI key:

```http
X-Scrinly-Provider-API-Key: $OPENAI_API_KEY
```

`Authorization` still carries the Scrinly key. The provider key is accepted only on screenshot requests with `styleGuide` enabled, is synchronous-only, and is never stored, echoed, logged, or added to a queue. BYOK is intended for server-to-server calls.

## Page credentials

For pages you are authorized to access, pass request headers through the JSON `headers` object and structured cookies through `cookies`. These values influence capture identity when screenshot caching is enabled, but cache keys contain only an opaque keyed fingerprint.

---
title: "Screenshot batches"
description: "Queue up to 100 stored screenshot jobs with partial acceptance."
---

Public `POST /render/batch` accepts only stored screenshot jobs. It requires `screenshot:true`, `store:true`, and a non-empty `storage_path`.

<CodeGroup>
```bash cURL
curl --request POST "https://api.scrinly.com/render/batch" \
  --header "Authorization: Bearer $SCRINLY_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"urls":["https://example.com","https://example.org"],"screenshot":true,"store":true,"storage_path":"batch"}'
```

```javascript JavaScript
const response = await fetch("https://api.scrinly.com/render/batch", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.SCRINLY_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    urls: ["https://example.com", "https://example.org"],
    screenshot: true,
    store: true,
    storage_path: "batch",
  }),
});
```

```python Python
import os, requests

response = requests.post(
    "https://api.scrinly.com/render/batch",
    headers={"Authorization": f"Bearer {os.environ['SCRINLY_API_KEY']}"},
    json={
        "urls": ["https://example.com", "https://example.org"],
        "screenshot": True,
        "store": True,
        "storage_path": "batch",
    },
)
```
</CodeGroup>

Each accepted URL becomes an independent async job billed at one credit. Screenshot viewport, cleanup, interaction, webhook, and public customer-storage options are supported. Structured extraction, regions, Visual Style Guide, and other add-ons are rejected because the batch reserves exactly one credit per item.

The route may return `207 Multi-Status`: valid items are queued, invalid items carry their own typed error, and rejected-item reservations are refunded. Poll each accepted job with `GET /status/{jobId}`. The limit is 100 URLs.

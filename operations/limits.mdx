---
title: "Platform limits"
description: "Current request, screenshot, diff, monitor, and result ceilings."
---

| Area | Limit |
| --- | --- |
| Screenshot viewport | 3840 × 2160 CSS pixels |
| Screenshot timeout | 10–60 seconds |
| Region crop height | 1,600 bitmap pixels |
| Region crop assets | 32 |
| Screenshot batch | 100 URLs |
| Diff JSON request | 2 MiB |
| Diff source body | 20 MiB each |
| Diff source pixels | 24 MP each; 40 MP combined |
| Diff source height | 32,768 pixels |
| Diff redirects | 3 safe redirects |
| Changed bounds | 128 after consolidation |
| Custom monitor recipients | 10 per account; 5 selected per monitor |
| Style Guide output | 6,144 tokens; 512 KiB provider response |
| Style Guide model deadline | 60 seconds |

Full-page preparation is capped to prevent infinite feeds from consuming a browser indefinitely. Scrinly returns `full_page_unbounded` when the document keeps growing and `full_page_incomplete` when capture dimensions remain shorter than the settled document after the retry.

Completed async metadata is bounded. If optional fields must be removed, the status result reports their names in `truncated`; stored direct media URLs remain available.

Monitor count, minimum cadence, and run retention depend on plan. See [Monitoring](/guides/monitoring#plans-and-retention).
